# SweetOh creative and production knowledge boundary

SweetOh AI is shared specialized intelligence used by future human creator tools and animal agents; it is not itself an agent. Canvas edits must remain typed, reviewable editor commands so users see the change, can undo it, and retain normal save and print-area validation.

## Knowledge model

Creative guidance should cover design fundamentals (composition, contrast, hierarchy, color, typography, illustration, repeat patterns, accessibility and file preparation) and broadly explain decoration methods. Store method guidance separately from SweetOh's current production capability. A general explanation is not a quote, an available option, or a promise that SweetOh can produce it.

| Method | General knowledge scope | SweetOh availability in this repository |
| --- | --- | --- |
| Sublimation | Substrate and transfer constraints; suitable raster/vector artwork | Not established by current production configuration |
| Engraving | Material, line-weight and depth constraints | Not established |
| DTF | Transparent artwork, fine detail and transfer constraints | Not established |
| DTG | Garment, opacity, underbase and raster constraints | Not established |
| Screen printing | Spot-color separations, trapping and minimum detail | Not established |
| Embroidery | Stitch density, underlay, pull compensation and digitization | Not established |
| HTV / cut vinyl | Weeding, mirrored cut files and minimum stroke constraints | Not established |

The codebase currently has a 300-DPI transparent print-file export and third-party catalog products, but no verified, authoritative registry of SweetOh-owned machines, substrates, methods, partner capabilities, or method-specific acceptance rules. Therefore every listed method stays educational only until operations/production data explicitly enables it. Product setup's existing “production method” language is not proof of an available method.

## Safe future structure

Keep method reference material versioned and source-attributed. Make capability a separate record keyed to an actual shop or approved production partner, method, supported material/product, printable area, color/file constraints, availability and effective dates. Quotes and accepted production orders must snapshot the enabled capability version and validated artwork requirements. Do not infer availability from a knowledge article or an AI response.

The current typed editor command schema has validated serializable operations for adding, editing, moving, sizing, rotating, aligning, styling, preparing artwork for a selected print region, history actions and deleting. It is a foundation only: no AI tool dispatches these commands yet, and the separate state schema is an intended read-only summary boundary. A future caller must pass through this same visible editor, history, validation and user review path.
